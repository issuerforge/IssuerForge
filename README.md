# IssuerForge

Випуск комплаєнс-нативних стейблкоїнів на Solana: правила виконуються самим
токеном, а не застосунком. Емітент складає політику в майстрі, підписує одну
транзакцію — і кожен переказ, з якого б гаманця його не зробили, проходить ту
саму перевірку.

- **Правила як конфігурація.** Одна перевірена ончейн-програма обслуговує всіх
  емітентів; політика кожного зберігається як дані й змінюється без повторного
  випуску токена і без міграції холдерів.
- **Комплаєнс-дії з доказом.** Заморозка рахунку, примусове стягнення й пауза
  обігу виконуються за кворумом 2-з-N і лишають журнал, який третя сторона
  звіряє з мережею, не довіряючи ані емітенту, ані платформі.
- **Емісія під резерв.** Випуск понад підтверджений резерв відхиляється мережею;
  публічна сторінка показує обіг, резерв і вік останньої атестації.

## Стек

pnpm workspaces · TypeScript · Anchor 0.32.1 / Token-2022 · Hono · Drizzle +
Postgres · React + Vite · Astro · Biome · Vitest

## Команди

```bash
pnpm install
pnpm dev         # усі застосунки паралельно
pnpm gate        # lint + typecheck + test
```

Збірка ончейн-програми — у WSL:

```powershell
wsl.exe -e bash /mnt/<шлях-до-репо>/scripts/wsl-build.sh
```

## Стан

Проєкт у розробці. Мережа — devnet; статуси верифікації, санкційний список,
банківський резерв і партнер off-ramp у демо фікстурні.
